How the platform works

Infrastructure

Separate Terraform modules organize networking, the EKS cluster, the database, image repositories and DNS. Environment configuration reuses those modules.

Delivery

Parallel image builds publish to Amazon ECR. Kustomize bases and environment overlays keep Kubernetes settings organized, while Argo CD manages the application resources.

Application access

Route 53 provides DNS. CloudFront connects to the application load balancer, and Kubernetes ingress routes requests to the frontend and API gateway. RDS MySQL supports the backend services.

Secrets and visibility

External Secrets Operator connects AWS Secrets Manager to Kubernetes secrets. Prometheus and Grafana provide workload metrics, with HPA scaling the application during simulated load.

What I explored

4 practical exercises
01

Making environments repeatable

How can I provision an environment without rebuilding every part by hand?

I split Terraform into reusable modules for the foundation, EKS, database, registry and DNS configuration. Environment settings connect those modules, with state stored in S3.

View Terraform modules View state backend
02

Connecting code to deployment

How can an application change reach Kubernetes through a clear delivery workflow?

GitHub Actions built the application images and published them to ECR. Argo CD managed the application resources from Git with Kustomize overlays. A recorded CI run completed in 3 minutes and 41 seconds.

Understanding workload behavior

How can I see the resources an application uses once it is running?

I configured Prometheus monitoring and used Grafana to inspect workload and cluster dashboards. The captures show CPU usage, resource quotas and memory across application namespaces.

Watching the platform respond to load
